# 主机版本与登录、sudo 凭据引用一次提交

共享主机库需要让两个 MCP 进程依据同一版本检测冲突。参考包分别提交主机档案与 sudo 凭据引用，会留下版本和引用部分更新的中间状态；因此将登录及 sudo 引用合并到 hosts.json 的主机记录中，在同一跨进程管理锁内原子提交，保持原有 JSON 和加密文件技术栈。

凭据内容仍由 AES-256-GCM vault 管理。先登记待清理 ID，再写入新凭据，随后提交主机引用，最后清理旧凭据；中断后只回收没有被现存主机引用的 ID。清理失败以 `cleanupPending: true` 明确返回，后续管理操作重试。此机制保证引用更新和恢复语义，不宣称多个文件具有断电事务保证。
