# Remote SSH MCP 实现设计

## 部署与数据归属

本项目是独立的 Node.js/TypeScript 包。SSH/SFTP、路径、文件、输出与凭据管理基于参考包适配，具体来源见 [NOTICE.md](../NOTICE.md)。

Codex CLI 与 Claude Code 分别启动一个标准 stdio MCP 子进程。两者使用同一个 WSL 用户数据目录，各自维护运行中的 SSH 连接与工作目录。不增加常驻 HTTP 服务或远端辅助程序。

默认数据目录为 `${XDG_DATA_HOME:-~/.local/share}/remote-ssh-mcp/`，可用 `REMOTE_SSH_MCP_DATA_DIR` 显式覆盖；与项目工作目录分离。两端配置必须解析到同一目录。沿用参考包的 JSON 文件、文件锁和加密凭据库，不引入数据库。

```text
~/.local/share/remote-ssh-mcp/
  hosts.json
  known-hosts.json
  pending-cleanup.json
  credentials/
    key
    vault.json
```

目录和凭据文件沿用参考包的 POSIX 权限检查，数据放在 WSL 用户文件系统。凭据库采用本地自动解锁，备份恢复需要匹配的 key 与 vault；密钥丢失或文件损坏时明确失败，不初始化覆盖旧资料。此设计不承诺断电时多个 JSON 文件具有数据库式事务一致性。

## MCP 工具

沿用原十个工具名与主要参数，仅替换 Pi 注册、渲染和凭据交互层：

| 工具 | 用途 |
| --- | --- |
| `ssh_list_hosts` | 列出主机 ID、版本、配置及当前连接上下文中的状态和目录；不返回凭据内容 |
| `ssh_set_workspace` | 设置当前连接上下文中某台主机的工作目录 |
| `ssh_shell_exec` | 同步执行命令，可使用 sudo，返回输出、退出状态及是否结果未知 |
| `ssh_read_file` / `ssh_write_file` | 有界文本读取与显式覆盖的写入 |
| `ssh_grep` / `ssh_glob` | 内容与路径搜索 |
| `ssh_upload_file` / `ssh_download_file` | 单文件流式传输 |
| `ssh_reset_connection` | 当前上下文显式重连，不重放命令 |

补足脱离 Pi 菜单后的管理入口：

| 工具 | 用途 |
| --- | --- |
| `ssh_add_host` | 新建主机，允许同时提供登录密码或私钥口令；返回 ID 和版本 |
| `ssh_update_host` | 按 ID 与 `expectedVersion` 更新配置；同名、过期版本及无效跳板引用报错 |
| `ssh_delete_host` | 按 ID 与版本删除档案，拒绝删除仍被其他档案引用的跳板 |
| `ssh_test_connection` | 临时测试 SSH/SFTP，不改变工作连接或目录 |
| `ssh_set_credentials` | 设置登录或 sudo 凭据，默认 `remember: true`；支持明确的 SSH 密码复用 |
| `ssh_forget_host_key` | 明确重置指定端点的信任记录，后续新连接按首次信任规则重新记录 |

所有涉及已有主机的工具要求稳定 `hostId`；新增使用唯一名称。管理工具结果返回最新版本，过期写入返回 `HOST_CONFLICT`，不替用户自动合并或重试。

缺少密码或私钥口令时立即返回 `CREDENTIAL_REQUIRED` 并指向设置工具，不等待无法显示的 Pi 弹窗。sudo 使用已配置凭据或显式指定的 SSH 密码复用；缺少凭据时明确失败，不自动重复执行用户命令。免密 sudo 保持可用。

响应使用 MCP 标准文本内容及结构化结果，保留错误码、退出码、截断标记和结果未知状态。stdout 只输出协议消息，诊断输出走 stderr 且不回显凭据；客户端如何显示进度由客户端决定，不重建 Pi 工具渲染界面。

## 共享与并发规则

- 每次工具操作开始时重新读取主机档案；同一用户数据目录使两个独立进程下一次调用即可看见已提交的变更。
- 写入在跨进程文件锁内重新读取并校验版本，然后原子替换文件。主机记录 version 用于修改冲突检测，连接配置 revision 用于判断是否必须重连；改名不会无故使连接失效。
- 主机和凭据管理遵循固定锁顺序；新加密凭据先写入，再提交引用，旧凭据清理不早于引用更新。删除先使档案不可用于新调用，再清理其凭据。故障不能被报告成完整成功，清理失败应可识别和恢复；不以多文件原子事务作未经验证的承诺。
- `remember: false` 的凭据只存在当前上下文并绑定连接身份，不把其他进程无法读取的临时凭据 ID 写成共享的有效凭据引用。临时使用不删除原来已记住的凭据；新建且仅有临时凭据的主机在其他客户端会明确报告缺少凭据。
- 连接配置或登录凭据变更使旧连接在下一次操作时返回需要重连；重连使用最新资料。sudo 凭据独立更新，不必仅为它重建 SSH 连接。
- 已开始操作使用开始时确定的主机和工作目录。删除档案阻止后续新调用，不通过强制断开正在使用的连接伪装成远程命令已停止；操作结束后或上下文释放时清理连接资源。
- 重置信任记录只改变后续连接的校验依据，不宣称已使其他进程当前的连接重新完成身份认证。对仍在执行的命令不自动重放。

## 验收矩阵

集成测试使用真实 OpenSSH 的 target、jump、no-sftp 容器及临时密钥。运行方式见 [开发与验证](../README.md#开发与验证)。

1. **协议及独立进程**：启动两个真正的 stdio MCP 子进程，完成 initialize、tools/list、tools/call；A 添加，B 查询并连接，再反向验证。不是在同一个进程里创建两个对象代替跨进程验证。
2. **重启与目录隔离**：两端设置不同远端目录互不影响；停止并重新启动 MCP 后，主机和已记住凭据保留，临时凭据消失，工作目录重置为 home。
3. **并发与可见性**：同时新增、同名新增、同一版本竞争更新、跨端改名、凭据变更与重连、删除后的调用失效、被引用跳板删除均有可重复断言；验证正在执行的命令不被删除流程强行断开或重放。
4. **凭据与故障恢复**：密码、加密私钥口令、sudo 独立密码及显式复用；临时覆盖不破坏已保存资料；损坏库或丢失 key 时失败并保留旧文件；故障注入覆盖凭据写入、引用提交与清理边界；响应和本服务日志不包含测试秘密。
5. **真实 SSH 行为**：命令、文本和二进制传输、覆盖保护、搜索、目录、跳板、sudo、无 SFTP、指纹变化、取消、超时、断线结果未知及不重放，复用隔离容器进行真实测试。
6. **可安装包**：TypeScript 检查、测试、构建及独立临时目录安装运行；确保包没有 Pi/OpenCode 运行依赖，也不引用原参考目录。
7. **真实客户端接入**：使用同一启动命令及数据目录配置 Codex CLI 和 Claude Code 的用户级 MCP；至少检查各自工具发现和连接状态。端到端工具调用证据须与 SDK 协议测试分别报告；若客户端认证或模型调用不可用，不把工具发现称为端到端通过。

实施时使用任务自建的容器、临时凭据和数据目录，不需要读取或连接用户现有生产主机。最终交付包括源码、锁文件、README、两端接入配置及分层的验证结果。

## 范围收束

Windows 原生、旧数据导入、额外本地输入界面、云端同步和持久后台任务均不属于首版。发布到公开包仓库不是本地实现和接入的必要步骤。

Q1–Q10 已获用户确认并授权实现。实现将登录与 sudo 凭据引用集中到 hosts.json 中，随版本一次提交；加密值仍在独立 vault 中，pending-cleanup.json 记录可恢复的清理工作。理由见 ADR-0003。
